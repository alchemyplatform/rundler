# Glamsterdam pre-verification gas

`preVerificationGas` pays the bundler back for the gas the EntryPoint does not meter. Under Glamsterdam, part of that gas depends on on-chain state (EIP-8037 state gas), so on a chain with a `glamsterdam_activation` rundler reads that state when it computes or checks PVG.

## Constant terms

Besides the schedule values in [Chain Specification](./chain_spec.md#glamsterdam-gas-schedule-values), the static PVG of every op adds `call_data_word_gas` (6 under Glamsterdam, 0 before) per 32-byte word of its `callData`. The EntryPoint ABI-encodes `callData` into memory for `innerHandleOp` and decodes it there, outside its metered spans. Measured on the devnet, that costs about 5 gas per word on top of what `per_user_op_word_gas` charges for every byte of the packed op. Other fields (signature, initCode, paymasterData) are not copied this way and keep the existing pricing.

## State-dependent terms

`UserOperation::required_pre_verification_gas(.., &PvgState)` applies two terms to the execution gas, before the calldata floor top-up:

- **Zero-deposit refund write**, `state_pre_verification_gas`: adds `zero_deposit_refund_gas` (97,920). A self-paying op (no paymaster) whose sender has a zero EntryPoint deposit has that deposit taken to the prefund and back to zero during validation. The refund in `_postExecution` then re-creates the slot after the EntryPoint stops metering, at the price of a new storage slot. This happens once per sender per bundle; rundler charges every op whose sender's deposit is zero, which overcharges a second op from the same sender in one bundle.
- **EIP-7702 authority state**, `authorization_state_discount`: `authorization_gas_limit` is the worst case, `eip7702_authorization_gas` (235,606, an authority that does not exist). If the authority exists, `eip7702_authorization_new_account_gas` (183,600) is subtracted. If it already has code, `eip7702_authorization_delegation_gas` (35,190) is subtracted as well, leaving 16,816.

`PvgState` holds the sender's deposit (is it zero?) and the authority state (`Missing`, `NoCode`, `HasCode`). Unknown values are priced as the worst case. Before Glamsterdam all four fields are 0, so both terms are 0. On a chain without an activation no state is read.

## Where the state is read

| Component | When | State read |
| --- | --- | --- |
| Gas estimation (`sim/src/estimation`) | `eth_estimateUserOperationGas` | latest block, without the user's state override |
| Precheck (`sim/src/precheck.rs`) | pool admission | latest block; the `PvgState` is kept on the pool entry |
| Pool maintenance (`pool/src/mempool/pool.rs`) | every block | the state captured at precheck |
| Builder (`builder/src/bundle_proposer.rs`) | each bundle proposal | the bundle's block: PVG is re-checked on L1 too, and the zero-deposit gas is added to the bundle gas limit |

All reads go through `rundler_sim::gas::load_pvg_state`. The state is read as soon as an activation is configured, also before it, so operations admitted before the fork are not repriced as the worst case after it. The bundle gas limit and the delegation sender keep pricing authorizations at the worst case. Before a timestamp activation every component prices with the bundle inclusion schedule, so the zero-deposit term already applies and no authorization gas is waived until the fork.

## Limits

- Metered bundles stay at or below the EIP-7825 cap (`transaction_gas_limit = 16777216`). Above it the EIP-8037 state-gas reservoir is non-empty, and the EntryPoint no longer sees the state gas the reservoir pays for. The one exception is a [reservoir-mode](#reservoir-mode) bundle, which goes above the cap on purpose.
- Whether calls get a reservoir depends on the client. reth v2.7 lifts the EIP-7825 cap for `eth_call`, `debug_traceCall` and `trace_call`, so the whole call gas is `gas_left` and state is charged to the frames' gas. besu, geth, Erigon, and reth after v2.7 (paradigmxyz/reth#27633) keep the cap, so a call's gas above 2^24 goes to a reservoir as in a transaction, and state the reservoir pays does not show in the frames' gas used. Keep `--max_gas_estimation_gas` at or below 2^24: below it no client gives a reservoir, so metered estimation sees all state gas everywhere.
- Clearing a slot that another op allocated earlier in the same bundle credits the refill to the `handleOps` frame, inside the clearing op's validation span. That lowers the clearing op's measured gas, and can make the EntryPoint's `gasleft()` subtraction underflow when the refill exceeds the span's own gas. Pricing does not address this.

## Reservoir mode

An op whose execution plus state gas does not fit under `max_bundle_execution_gas` is bundled alone, with `tx.gas = 2^24 + R`. A contract deployment near the EIP-170 limit is the main example: it needs about 38M of state gas. The transaction's state-gas reservoir is then exactly `R`, which pays for the op's state; the EntryPoint does not see that gas, so the op pays for it through PVG. `StateGasMode::{Metered, Reservoir}` names the two modes.

Reservoir mode only applies while Glamsterdam is active (`ChainSpec::reservoir_mode_enabled_at`), on v0.7+ entry points, and not to aggregated ops. Bundler-sponsored ops sign with PVG = 0, so their reservoir is found at admission (below). Measurements and the design are in `test/pvg-calibration/docs/reservoir-mode-plan.md`.

| Component | What it does |
| --- | --- |
| Gas estimation (`sim/src/estimation/v0_7.rs`) | Normal (metered) estimation first. If that fails in a way more gas could fix, the estimator falls back to reservoir mode, which runs everything in `eth_simulateV1` (`simulate_call` / `simulate_calls`): on reth v2.7 it gives a call above 2^24 a reservoir as a transaction gets (unlike `eth_call`), under a raised block gas limit, and under the user's state override merged with the simulation's. First `simulateHandleOp` of the op, with postOp, at the most call gas and `2^24 + --max_reservoir_gas`, measures the op's net state gas `S`: the transaction's gas used, less the gas the EntryPoint metered (its `UserOperationEvent.actualGasUsed`, less the penalty on unused execution gas, from `preOpGas` and the limits), the transaction's intrinsic gas and the simulation's own unmetered work (20,000; 20,783 measured on Sepolia). `S` is approximate: refunds, e.g. for cleared slots, lower the gas used, so it errs low for an op that clears state (churn(400,200): 17.60M against 19.58M net); on Sepolia it is otherwise within about 5,000 above the net state. It is only where the searches start, which run the op at the reservoir and limits it gets, so an `S` that is low spills into the call gas, where the search counts it. An op that fails here fails even with the most reservoir and call gas, and returns the metered error; With `S` below one slot (97,920), the op has no net state: if it runs at `R = S` (the call gas search below passes), its metered estimate failed for another reason, and the metered error is returned too. An op that clears all the state it allocates also has no net state, but its peak needs a reservoir, which the search finds. The existing call gas search (`CallGasEstimationProxy`, as `simulateHandleOpNoPostOp`'s target) runs there at `tx.gas = 2^24 + S`: any state the op peaks at above `S` (an op that allocates state and clears it again) spills into its call gas, which the search counts, and the refill gives it back to the frame. If that spill does not fit the most call gas, a search (4 parallel guesses per round of the proxy's `testCallGas`, 1% tolerance) finds the least `R` the op runs with at the most call gas, up to `--max_reservoir_gas`, and the call gas search runs again at that `R`. The least `R` is the cheapest for the op: PVG pays for all of `R`, while gas that spills into the call gas limit and comes back costs at most the unused-gas penalty. The most call gas is what fits under `--max_bundle_execution_gas` next to the op's other limits (the EntryPoint needs 64/63 of it before execution), with the op's calldata priced at its worst case (`max_fill`), since the signature, paymaster data and PVG sent are not the estimate's and a call gas limit at the most has no headroom, and what a simulation can give the sender below 2^24. The searches leave postOp out, so the op is then simulated with postOp at its limits and that `R`; if it fails, the metered error is returned. The same `eth_simulateV1` request first calls a `ReservoirProbe` (by state override), which tells whether this node's `eth_simulateV1` gives calls a reservoir, as all of these simulations rely on (reth v2.7 does; geth from v1.17.8 does not): its inner call has less gas than one new slot's state gas, writes a slot and reverts, so it reaches its revert only if a reservoir pays the slot. It is its own call rather than `simulateHandleOp`'s target, which would see only what the op left of the reservoir. If it finds none, the metered error is returned (counted in `reservoir_simulation_without_reservoir`). The estimate is: VGL metered, CGL the search's result plus the usual buffer, PVG = required + `R`. PVG must pay for all of `R`, not just `S`: the bundle's reservoir is the PVG surplus, and state the reservoir pays is not metered by the EntryPoint, so an op that used more of it onchain than in simulation (execution may branch on block values) would otherwise get that state for free. An op that behaves as simulated uses `S`, and the rest of `R` is refunded to the bundler. All of it shares `--reservoir_trace_timeout_ms`. A new EIP-7702 authority's state (183,600 + 35,190) is added to `R`: the reservoir pays for it before the EntryPoint runs, but the trace and simulations apply the delegation by state override and do not show it. Self-paying ops always include the zero-deposit term, since the deposit may be zero by admission. The reservoir is kept at least one slot of state gas (97,920) above `gas::reservoir_threshold`, checked against the final op, so admission still classifies the op as reservoir mode if its threshold rises a little (e.g. shorter paymaster data or a lower limit). If `R` is below that, it is padded. This happens because the metered call gas limit needs more than the state itself (search tolerance, 1/64 per nested call), so such an op fits neither mode otherwise. Padding means admission still classifies the op as reservoir mode, at a small overpayment that is refunded to the bundler. A copy that also fails, or an op without state gas, returns the metered error. |
| Precheck (`sim/src/precheck.rs`) | No tracing. An op is in reservoir mode iff its PVG surplus over the metered requirement is at least `gas::reservoir_threshold` (the least state gas that cannot fit next to its computation gas). `R` is that surplus, bounded by `--max_reservoir_gas`. A bundler-sponsored or aggregated op whose surplus reaches the threshold is rejected (`ReservoirGasTooHigh` with a max of 0), since it would be bundled metered with an execution-only call gas limit. These ops are checked against `--max_reservoir_uo_cost` instead of `--max_uo_cost`. |
| Admission of bundler-sponsored ops (`sim/src/estimation/reservoir.rs`, `ReservoirEstimator::sponsored_reservoir_gas`) | A sponsored op's PVG is zero, so it carries no reservoir; the pool's precheck finds one with estimation's simulations, at the op's signed limits. Only for an op that passes the cheaper checks (init code, EIP-7702, payer). The op is first run in `eth_simulateV1` without a reservoir, and without the `ReservoirProbe`, so it runs on any node; if it succeeds, it is admitted metered. Otherwise `S` is measured; `R = S` if the op runs with it, else the least `R` up to `--max_reservoir_gas` (the same parallel search); an op that fails even with the most reservoir is admitted metered, as any sponsored op whose execution fails. A new EIP-7702 authority's state is added to `R`. Only the search takes a permit (`--max_concurrent_sponsored_reservoir_searches`, separate from estimation's) and is bounded by `--reservoir_trace_timeout_ms`. An op whose reservoir cannot be found is rejected: `ReservoirSearchBusy` or `ReservoirSearchTimedOut` (retryable), or `ReservoirSimulationUnsupported` when the node's `eth_simulateV1` gives calls no reservoir. Admitting it metered would have the bundler pay for a failure. The pool builds no search without reservoir mode (`--max_reservoir_gas 0` or no Glamsterdam). |
| Pool (`pool/src/mempool`) | Stores `R` (`PoolOperation::reservoir_gas`, also over the remote pool). The re-check requires PVG >= required + `R`, and marks the op ineligible otherwise; it is never moved to a metered bundle. Caps: `--pool.max_reservoir_ops`, `--pool.max_reservoir_ops_per_sender`. |
| Builder (`builder/src/assigner.rs`, `bundle_proposer.rs`) | Assigns each reservoir-mode op alone (own slots, pinned for fee-bump replacements; with one signer, reservoir mode and normal work take turns), and sends it with `tx.gas = TX_MAX_GAS_LIMIT + R`, with no overhead multiplier. At bundle time PVG must still cover required + `R`. Before sending, the bundle is simulated as it will be sent with `eth_simulateV1` (`simulate_call`), which gives it the transaction's reservoir; an `eth_call` on reth v2.7 gets none. The op is rejected if `handleOps` reverts (a `FailedOp` is handled as for any bundle), or if its `actualGasUsed` is below the simulated transaction's gas used, which would be the bundler's loss. An op whose own execution fails is still sent, as in a normal bundle, since it is charged in full. |

When the op settles normally, the bundler recovers its state cost: `R` comes from what the op paid, and state the EntryPoint does not see is at most `R`. State beyond `R` spills into the op's own metered gas, which the user pays.

The charging contract is prepaid capacity, not exact state billing. The user or paymaster pays the fixed PVG, including all of `R` (and any padding above `S`), whatever state the op actually creates. The unused part of the reservoir is refunded to the bundler, the transaction's sender, not to the user or paymaster.

A full-transaction revert (e.g. AA95, or a failed validation at bundle time) charges no state gas, but it also undoes the EntryPoint's compensation, so the bundler pays the execution gas used, up to 2^24, as for any reverted bundle.

Requirements: the node's `eth_simulateV1` must give calls a state-gas reservoir (reth v2.7 does; geth from v1.17.8 does not), which a `ReservoirProbe` checks, and its `rpc.gascap` must allow calls of `2^24 + --max_reservoir_gas`. No EIP-8037 tracing is needed.

Metrics: `gas_estimator.reservoir_{fallbacks,estimates,fallbacks_busy}`, `reservoir_trace_ms`, `reservoir_state_gas`, `reservoir_peak_searches` and `reservoir_simulation_without_reservoir`; `op_pool.num_reservoir_ops_added` and `op_pool.num_reservoir_ops`; `builder.reservoir_bundles_mined`, `reservoir_bundle_reservoir_gas`, `reservoir_bundle_charged_gas` and `reservoir_bundle_gas_used` (margin = charged - used).
