# Glamsterdam pre-verification gas

`preVerificationGas` pays the bundler back for the gas the EntryPoint does not meter. Under Glamsterdam, part of that gas depends on on-chain state (EIP-8037 state gas), so on a chain with a `glamsterdam_activation` rundler reads that state when it computes or checks PVG.

## Constant terms

Besides the schedule values in [Chain Specification](./chain_spec.md#glamsterdam-gas-schedule-values), the static PVG of every op adds `call_data_word_gas` (6 under Glamsterdam, 0 before) per 32-byte word of its `callData`. The EntryPoint ABI-encodes `callData` into memory for `innerHandleOp` and decodes it there, outside its metered spans. Measured on the devnet, that costs about 5 gas per word on top of what `per_user_op_word_gas` charges for every byte of the packed op. Other fields (signature, initCode, paymasterData) are not copied this way and keep the existing pricing.

## State-dependent terms

`UserOperation::required_pre_verification_gas(.., &PvgState)` applies two terms to the execution gas, before the calldata floor top-up:

- **Zero-deposit refund write**, `state_pre_verification_gas`: adds `zero_deposit_refund_gas` (97,920). A self-paying op (no paymaster) whose sender has a zero EntryPoint deposit has that deposit taken to the prefund and back to zero during validation. The refund in `_postExecution` then re-creates the slot after the EntryPoint stops metering, at the price of a new storage slot. This happens once per sender per bundle; rundler charges every op whose sender's deposit is zero, which overcharges a second op from the same sender in one bundle.
- **EIP-7702 authority state**, `authorization_state_discount`: `authorization_gas_limit` is the worst case, `eip7702_authorization_gas` (235,606, an authority that does not exist). If the authority exists, `eip7702_authorization_new_account_gas` (183,600) is subtracted. If it already has code, `eip7702_authorization_delegation_gas` (35,190) is subtracted as well, leaving 16,816.

`PvgState` holds the sender's deposit (is it zero?) and the authority state (`Missing`, `NoCode`, `HasCode`). Unknown values are priced as the worst case. Before Glamsterdam all four fields are 0, so both terms are 0. On a chain without an activation no state is read.

## Where the state is read

| Component | When | State read |
| --- | --- | --- |
| Gas estimation (`sim/src/estimation`) | `eth_estimateUserOperationGas` | latest block, without the user's state override |
| Precheck (`sim/src/precheck.rs`) | pool admission | latest block; the `PvgState` is kept on the pool entry |
| Pool maintenance (`pool/src/mempool/pool.rs`) | every block | the state captured at precheck |
| Builder (`builder/src/bundle_proposer.rs`) | each bundle proposal | the bundle's block: PVG is re-checked on L1 too, and the zero-deposit gas is added to the bundle gas limit |

All reads go through `rundler_sim::gas::load_pvg_state`. The state is read as soon as an activation is configured, also before it, so operations admitted before the fork are not repriced as the worst case after it. The bundle gas limit and the delegation sender keep pricing authorizations at the worst case. Before a timestamp activation every component prices with the bundle inclusion schedule, so the zero-deposit term already applies and no authorization gas is waived until the fork.

## Limits

- Metered bundles stay at or below the EIP-7825 cap (`transaction_gas_limit = 16777216`). Above it the EIP-8037 state-gas reservoir is non-empty, and the EntryPoint no longer sees the state gas the reservoir pays for. The one exception is a [reservoir-mode](#reservoir-mode) bundle, which goes above the cap on purpose.
- Whether calls get a reservoir depends on the client. reth v2.7 lifts the EIP-7825 cap for `eth_call`, `debug_traceCall` and `trace_call`, so the whole call gas is `gas_left` and state is charged to the frames' gas. besu, geth, Erigon, and reth after v2.7 (paradigmxyz/reth#27633) keep the cap, so a call's gas above 2^24 goes to a reservoir as in a transaction, and state the reservoir pays does not show in the frames' gas used. Keep `--max_gas_estimation_gas` at or below 2^24: below it no client gives a reservoir, so metered estimation sees all state gas everywhere.
- Clearing a slot that another op allocated earlier in the same bundle credits the refill to the `handleOps` frame, inside the clearing op's validation span. That lowers the clearing op's measured gas, and can make the EntryPoint's `gasleft()` subtraction underflow when the refill exceeds the span's own gas. Pricing does not address this.

## Reservoir mode

An op whose execution plus state gas does not fit under `max_bundle_execution_gas` is bundled alone, with `tx.gas = 2^24 + R`. A contract deployment near the EIP-170 limit is the main example: it needs about 38M of state gas. The transaction's state-gas reservoir is then exactly `R`, which pays for the op's state; the EntryPoint does not see that gas, so the op pays for it through PVG. `StateGasMode::{Metered, Reservoir}` names the two modes.

Reservoir mode only applies while Glamsterdam is active (`ChainSpec::reservoir_mode_enabled_at`), on v0.7+ entry points, and not to bundler-sponsored or aggregated ops. Measurements and the design are in `test/pvg-calibration/docs/reservoir-mode-plan.md`.

| Component | What it does |
| --- | --- |
| Gas estimation (`sim/src/estimation/v0_7.rs`) | Normal (metered) estimation first. If that fails in a way more gas could fix, the estimator traces the op's net state gas `S` on a copy with raised call-gas and postOp limits (`get_state_gas_simulate_handle_op_call` + `trace_call_state_gas`, `callTracer` root `stateGasUsed`), under the user's state override merged with the simulation's. The trace calls a `ReservoirProbe` (by state override) as `simulateHandleOp`'s target, which tells whether this node gives calls a reservoir: its inner call has less gas than one new slot's state gas, writes a slot and reverts, so it reaches its revert only if a reservoir pays the slot. The revert keeps `S` unchanged, and the probe runs on the same node as the trace. Without a probe result the metered error is returned. The copy's call gas holds the op's state, which only works where calls get no reservoir (reth v2.7), so on a node that gives them one estimation fails closed for now: it returns the metered error (counted in `reservoir_in_calls`). The reservoir `R` and the call gas limit then come from `eth_simulateV1` (`simulate_call`), which on reth v2.7 gives a call above 2^24 a reservoir as a transaction gets, under a raised block gas limit. The existing call gas search (`CallGasEstimationProxy`, as `simulateHandleOpNoPostOp`'s target) runs there at `tx.gas = 2^24 + S`: any state the op peaks at above `S` (an op that allocates state and clears it again) spills into its call gas, which the search counts, and the refill gives it back to the frame. If that spill does not fit the most call gas, a search (4 parallel guesses per round of the proxy's `testCallGas`, 1% tolerance) finds the least `R` the op runs with at the most call gas, up to `--max_reservoir_gas`, and the call gas search runs again at that `R`. The least `R` is the cheapest for the op: PVG pays for all of `R`, while gas that spills into the call gas limit and comes back costs at most the unused-gas penalty. The most call gas is what fits under `--max_bundle_execution_gas` next to the op's other limits (the EntryPoint needs 64/63 of it before execution), and what a simulation can give the sender below 2^24. The searches leave postOp out, so the op is then simulated with postOp at its limits and that `R`; if it fails, the metered error is returned. The estimate is: VGL metered, CGL the search's result plus the usual buffer, PVG = required + `R`. PVG must pay for all of `R`, not just `S`: the bundle's reservoir is the PVG surplus, and state the reservoir pays is not metered by the EntryPoint, so an op that used more of it onchain than in simulation (execution may branch on block values) would otherwise get that state for free. An op that behaves as simulated uses `S`, and the rest of `R` is refunded to the bundler. All of it shares `--reservoir_trace_timeout_ms`. A new EIP-7702 authority's state (183,600 + 35,190) is added to `R`: the reservoir pays for it before the EntryPoint runs, but the trace and simulations apply the delegation by state override and do not show it. Self-paying ops always include the zero-deposit term, since the deposit may be zero by admission. The reservoir is kept at least one slot of state gas (97,920) above `gas::reservoir_threshold`, checked against the final op, so admission still classifies the op as reservoir mode if its threshold rises a little (e.g. shorter paymaster data or a lower limit). If `R` is below that, it is padded. This happens because the metered call gas limit needs more than the state itself (search tolerance, 1/64 per nested call), so such an op fits neither mode otherwise. Padding means admission still classifies the op as reservoir mode, at a small overpayment that is refunded to the bundler. A copy that also fails, or an op without state gas, returns the metered error. |
| Precheck (`sim/src/precheck.rs`) | No tracing. An op is in reservoir mode iff its PVG surplus over the metered requirement is at least `gas::reservoir_threshold` (the least state gas that cannot fit next to its computation gas). `R` is that surplus, bounded by `--max_reservoir_gas`. A bundler-sponsored or aggregated op whose surplus reaches the threshold is rejected (`ReservoirGasTooHigh` with a max of 0), since it would be bundled metered with an execution-only call gas limit. These ops are checked against `--max_reservoir_uo_cost` instead of `--max_uo_cost`. |
| Pool (`pool/src/mempool`) | Stores `R` (`PoolOperation::reservoir_gas`, also over the remote pool). The re-check requires PVG >= required + `R`, and marks the op ineligible otherwise; it is never moved to a metered bundle. Caps: `--pool.max_reservoir_ops`, `--pool.max_reservoir_ops_per_sender`. |
| Builder (`builder/src/assigner.rs`, `bundle_proposer.rs`) | Assigns each reservoir-mode op alone (own slots, pinned for fee-bump replacements; with one signer, reservoir mode and normal work take turns), and sends it with `tx.gas = TX_MAX_GAS_LIMIT + R`, with no overhead multiplier. At bundle time PVG must still cover required + `R`. Before sending, the bundle is simulated as it will be sent with `eth_simulateV1` (`simulate_call`), which gives it the transaction's reservoir; an `eth_call` on reth v2.7 gets none. The op is rejected if `handleOps` reverts (a `FailedOp` is handled as for any bundle), or if its `actualGasUsed` is below the simulated transaction's gas used, which would be the bundler's loss. An op whose own execution fails is still sent, as in a normal bundle, since it is charged in full. |

When the op settles normally, the bundler recovers its state cost: `R` comes from what the op paid, and state the EntryPoint does not see is at most `R`. State beyond `R` spills into the op's own metered gas, which the user pays.

The charging contract is prepaid capacity, not exact state billing. The user or paymaster pays the fixed PVG, including all of `R` (and any padding above `S`), whatever state the op actually creates. The unused part of the reservoir is refunded to the bundler, the transaction's sender, not to the user or paymaster.

A full-transaction revert (e.g. AA95, or a failed validation at bundle time) charges no state gas, but it also undoes the EntryPoint's compensation, so the bundler pays the execution gas used, up to 2^24, as for any reverted bundle.

Requirements: the node must report EIP-8037 gas on the `callTracer` root frame (reth does). Its `rpc.gascap` must allow estimation's trace, which needs about the verification gas + `max_bundle_execution_gas` + `--max_reservoir_gas`, and that reservoir amount again when a paymaster pays.

Metrics: `gas_estimator.reservoir_{fallbacks,estimates,fallbacks_busy}`, `reservoir_trace_ms`, `reservoir_state_gas`, `reservoir_peak_searches` and `reservoir_in_calls`; `op_pool.num_reservoir_ops_added` and `op_pool.num_reservoir_ops`; `builder.reservoir_bundles_mined`, `reservoir_bundle_reservoir_gas`, `reservoir_bundle_charged_gas` and `reservoir_bundle_gas_used` (margin = charged - used).
